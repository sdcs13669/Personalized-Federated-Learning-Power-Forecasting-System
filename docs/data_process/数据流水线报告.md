### 1.2 统一清洗流程

所有数据集经过相同的清洗流水线，脚本位于 `data/scripts/clean-feature-engneer/`：

| 步骤          | 操作                                                   | 参数                         |
| ------------- | ------------------------------------------------------ | ---------------------------- |
| 1. 时间解析   | 解析 datetime 列，处理多种日期格式（含 DD/MM/YYYY）    | `dayfirst` 自动检测        |
| 2. 重采样     | 统一到**30min** 粒度，取均值                     | `resample("1800s").mean()` |
| 3. 首部修剪   | 去除首个有效值之前的 leading zeros/NaN（设备未投运）   | 从首个 >0 有效值开始         |
| 4. 连续性过滤 | 剔除原始最大连续缺口 >48 步（24h）的序列               | `MAX_GAP_DROP = 48`        |
| 5. 异常检测   | 标签用**diff IQR**，特征用 **rolling IQR** | 系数 2.5~3.0（按数据集调节） |
| 6. 物理裁剪   | 施加物理边界限制（功率>0, 功率因数[0,1]）              | 数据集特定                   |
| 7. 二次过滤   | 剔除清洗后最大连续缺口 >48 步的序列                    | `MAX_GAP_DROP = 48`        |
| 8. 插值填充   | Cubic spline（仅内部填充，首尾 NaN 保留）              | `limit_area="inside"`      |
| 9. 物理裁剪   | —                                                     | —                           |
| 10. 特征工程  | 派生 8 个公共时间特征（见 §2）                        | —                           |

### 1.3 异常检测策略

**标签列（功率负荷）—— diff IQR**：

```
d = s.diff()                           # 一阶差分（相邻步变化率）
q1, q3 = d.quantile(0.25), d.quantile(0.75)
IQR = q3 - q1
异常 if |d| > q3 + k × IQR  (k 默认 2.5)
```

**为什么不用 rolling IQR？** 电力负荷有 3~5 倍的昼夜/周度周期性波动。rolling IQR 会把合法的峰谷误判为异常，导致过度平滑。diff IQR 检查的是**变化率**而非绝对值，只在出现不可能的变化速度时才标记，不会伤害正常周期的峰谷。

**特征列（无功功率、CO2、功率因数、气象）—— rolling IQR**：

```
窗口 = 336 步（7 天 @30min），center=True
异常 if value ∉ [Q1(win) - k×IQR(win), Q3(win) + k×IQR(win)]  (k 默认 2.5)
```

特征没有目标列那种剧烈的昼夜波动，rolling IQR 可以检测相对于局部模式的偏离。

## 2. 特征工程

### 2.1 公共特征（8 维，所有数据集共享）

Global TCN encoder 的固定输入通道，跨联邦客户端统一：

| 特征            | 公式                     | 取值范围 | 物理含义                                   |
| --------------- | ------------------------ | -------- | ------------------------------------------ |
| `hour_sin`    | sin(2π × hour/24)      | [-1, 1]  | 小时正弦编码，捕捉日内周期                 |
| `hour_cos`    | cos(2π × hour/24)      | [-1, 1]  | 小时余弦编码，与 hour_sin 互补定位         |
| `dow_sin`     | sin(2π × dow/7)        | [-1, 1]  | 星期正弦编码（周一=0, 周日=6）             |
| `dow_cos`     | cos(2π × dow/7)        | [-1, 1]  | 星期余弦编码                               |
| `is_weekend`  | 1 if dow≥5 else 0       | {0, 1}   | 周末标志                                   |
| `month_sin`   | sin(2π × (month-1)/12) | [-1, 1]  | 月正弦编码，捕捉年周期                     |
| `month_cos`   | cos(2π × (month-1)/12) | [-1, 1]  | 月余弦编码                                 |
| `category_id` | 0/1/2                    | {0,1,2}  | 数据集类别编码（0=居民, 1=变压器, 2=工业） |

> 选择 sin/cos 双通道编码而非单整数编码的原因：保证 0 点和最大值点的连续性（如 23 时和 0 时在 sin/cos 空间中相邻），避免模型将相邻时刻误学为远距离。

### 2.2 本地特征（数据集特定，仅残差修正器使用）

特征筛选后确定的最终本地特征（详见 §3）：

| 数据集       | 维度        | 特征                                                                                      |
| ------------ | ----------- | ----------------------------------------------------------------------------------------- |
| eld_ind      | **0** | 无（宽表，所有列为目标负荷）                                                              |
| lcl_res      | **0** | 无（tariff_type 为常量，已剔除）                                                          |
| steel_ind    | **4** | `co2`, `lagging_reactive_power`, `lagging_pf`, `load_type`                        |
| tetouan_city | **5** | `temperature`, `humidity`, `wind_speed`, `general_diffuse_flow`, `diffuse_flow` |

## 3. 特征筛选

### 3.1 筛选方法

使用自动化脚本 `data/scripts/feature-select/feature_select.py`（单目标）和 `feature_select_batch.py`（宽表聚合），流程：

1. **缺失率检测** — 标记 >50% 的列
2. **常量检测** — 标记单一值的列
3. **Pearson 相关性** — 标记 |r| > 0.9 的特征对
4. **VIF（方差膨胀因子）** — 标记 >10 的列
5. **XGBoost 训练** — 时序 70/15/15 划分，early stopping
6. **SHAP 分析** — TreeExplainer 计算 mean |SHAP|，输出 bar + beeswarm 图

### 3.2 筛选结果

#### 3.2.1 steel_ind（钢铁工业）

| 特征                       | SHAP  | 占比 | 决策                                                      |
| -------------------------- | ----- | ---- | --------------------------------------------------------- |
| `co2`                    | 11.26 | —   | **保留** — CO2 排放是钢厂负荷的最强代理变量        |
| `lagging_reactive_power` | 8.80  | —   | **保留** — 感应电机无功功率                        |
| `load_type`              | 4.13  | —   | **保留** — 轻/中/满载三档分类                      |
| `lagging_pf`             | 1.27  | —   | **保留** — 滞后功率因数，提供增量信息              |
| `leading_reactive_power` | 0.24  | <1%  | **剔除** — SHAP 极低，与 leading_pf 冗余(r=-0.950) |
| `leading_pf`             | 0.21  | <1%  | **剔除** — SHAP 极低，容性补偿对负荷预测无帮助     |

R² = 0.834。本地特征 6→4 维。详见 `steel_ind_Usage_kWh_shap.yaml`。

#### 3.2.2 tetouan_city（城市配电网，3 Zone）

| 特征                     | Zone1 SHAP | Zone2 SHAP | Zone3 SHAP | 决策                                               |
| ------------------------ | ---------- | ---------- | ---------- | -------------------------------------------------- |
| `temperature`          | 727        | 607        | 508        | **保留** — 三区一致，气温是最重要的气象因子 |
| `general_diffuse_flow` | 325        | 285        | 326        | **保留** — 日照强度                         |
| `diffuse_flow`         | 244        | 71         | 121        | **保留** — 与 general 相关(r=0.879)但 VIF<5 |
| `humidity`             | 116        | 79         | 88         | **保留** — 湿度影响空调负荷                 |
| `wind_speed`           | 93         | 124        | 187        | **保留** — 风速影响散热                     |

5 维气象特征全部保留（VIF 均 <5，物理意义明确）。时间特征贡献最大（hour_sin SHAP 2508~4371）。详见 `tetouan_city_load_zone1/2/3_shap.yaml`。

#### 3.2.3 eld_ind（变压器，聚合 326 条 MT）

| 特征            | Mean\|SHAP\| | ± Std  |
| --------------- | ------------ | ------- |
| `hour_sin`    | 182.68       | 1380.27 |
| `hour_cos`    | 91.64        | 476.90  |

#### 3.2.4 lcl_res（居民，聚合 321 户）

| 特征            | Mean\|SHAP\| | ± Std |
| --------------- | ------------ | ------ |
| `hour_sin`    | 0.058        | 0.058  |

| `hour_cos`    | 0.036        | 0.052  |
| `month_sin`   | 0.013        | 0.018  |
| `dow_sin`     | 0.010        | 0.011  |

R² mean=0.128, median=0.224。时间特征对居民用电解释力极弱（高度随机），验证了个性化残差修正器的必要性。`is_weekend` SHAP≈0（伦敦居民周末无差异化用电模式）。详见 `lcl_res_aggregate_shap.yaml`。

### 3.3 筛选原则总结

| 原则         | 应用                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 缺失率过滤   | 各组目标列缺失率均 <7%，无剔除                                                                         |
| 常量过滤     | 剔除 `tariff_type`(lcl)；`category_id` 虽是单数据集常量但跨数据集变化 → **保留**            |
| 相关性 + VIF | 剔除 `leading_reactive_power` + `leading_pf`(steel, SHAP<1%+冗余)                                  |
| XGBoost+SHAP | 自动化脚本逐数据集验证；eld/lcl 聚合均值，steel/tetouan 按目标列独立分析                               |
| 宁留勿删     | `is_weekend`(SHAP≈0), `diffuse_flow`(r=0.879) 均保留。8 个公共特征为固定 encoder 输入，不参与剔除 |

## 4. 客户端数据划分

### 4.1 划分原则

- 不按大规模 FL 客户端划分（如 69 客户端），改为**少量客户端**以加快实验迭代速度
- 划分基于**序列有效长度**（天数），模拟不同数据成熟度的客户端
- steel_ind 和 tetouan_city 各序列直接作为一个客户端
- 配置文件：`fl_code/models/client_config.yaml`，代码可直接凭此提取序列

### 4.2 最终划分方案（9 客户端）

| 数据集       | 客户端             | 序列数    | 长度范围      | 公共特征 | 本地特征 |
| ------------ | ------------------ | --------- | ------------- | -------- | -------- |
| steel_ind    | `steel_ind_0`    | 1         | 365天         | 8        | 4        |
| tetouan_city | `tetouan_city_0` | 1 (Zone1) | 364天         | 8        | 5        |
| tetouan_city | `tetouan_city_1` | 1 (Zone2) | 364天         | 8        | 5        |
| tetouan_city | `tetouan_city_2` | 1 (Zone3) | 364天         | 8        | 5        |
| lcl_res      | `lcl_res_0`      | 145 MAC   | <730天        | 8        | 0        |
| lcl_res      | `lcl_res_1`      | 176 MAC   | ≥730天       | 8        | 0        |
| eld_ind      | `eld_ind_0`      | 14 MT     | [365, 730)天  | 8        | 0        |
| eld_ind      | `eld_ind_1`      | 15 MT     | [730, 1095)天 | 8        | 0        |
| eld_ind      | `eld_ind_2`      | 313 MT    | ≥1095天      | 8        | 0        |

### 4.3 各数据集划分细节

**eld_ind**（361 MT → 342 MT 可用 + 19 剔除 → 3 客户端）：

- 剔除 19 条 <365 天的短序列（MT_106~113, MT_115~117, MT_120~122, MT_133, MT_160, MT_178, MT_181, MT_337）
- `eld_ind_0`: 14 MT，长度 [365, 730) 天
- `eld_ind_1`: 15 MT，长度 [730, 1095) 天
- `eld_ind_2`: 313 MT，长度 ≥1095 天

**lcl_res**（321 MAC → 2 客户端）：

- `lcl_res_0`: 145 MAC，长度 <730 天（含 6 条 <548 天 + 139 条 [548, 730) 天）
- `lcl_res_1`: 176 MAC，长度 ≥730 天

**steel_ind**（1 客户端）：整个数据集作为一条序列，`Usage_kWh`。

**tetouan_city**（3 客户端）：Zone1（工业）、Zone2（混合）、Zone3（居民）各为一个客户端。
