**镜头 1.2（0:20–1:00）痛点示意（PPT 单页：数据孤岛 vs 联合建模）**
【画面】PPT：四个主体（钢厂/城市分区/居民社区/工业园区）数据不出域，中间是联邦平台

### S2 总体架构（1:00–2:30，约 460 字）

**镜头 2.1（1:00–2:00）架构图 + 全链路映射**
【画面】PPT 架构图：中心侧平台（FastAPI + Flower 联邦框架 + 审计库）↕ 客户端代理（采集/训练/本地修正），标注 HTTPS 与 gRPC；四条链路逐个高亮
【逐字稿】
先看总体架构。系统由三部分组成：中心侧是联邦学习服务平台，基于 FastAPI 与 Flower 联邦学习框架构建，负责任务管理、安全聚合与全程审计；参与侧是轻量客户端代理，一条命令即可部署，内置数据采集、联邦训练与本地个性化建模；两端通过标准 HTTPS 与 gRPC 协议，在真实网络上通信。
对照榜题"可信采集—安全传输—可控使用—可溯监管"的全链路要求：**可信采集**环节，客户端从指定数据源下载数据并本地校验，校验统计留存在参与方本地；**安全传输**环节，全部交互走 HTTPS 与 gRPC，加入任务凭一次性密钥，服务端只保存密钥的 SHA-256 哈希；**可控使用**环节，差分隐私在客户端梯度层生效——逐样本梯度裁剪加高斯噪声，服务器只见加噪参数，永远接触不到原始数据与未加噪梯度，隐私预算按客户端逐轮计量；**可溯监管**环节，每一轮的参与情况、损失、裁剪阈值、隐私预算全部写入审计库，管理端大屏实时可视，形成完整审计链。

**镜头 2.2（2:00–2:30）两阶段模型示意**
【画面】PPT：全局 TCN → Y_pre；本地残差修正器 → P10/P50/P90
【逐字稿】
模型采用两阶段架构：第一阶段，各参与方联合训练全局 TCN 时序卷积网络，输入三天历史负荷与公共特征，输出未来三小时的预测；第二阶段，每一方在本地训练一个残差修正器，只用本地数据、永不共享，对全局预测做个性化校正，并输出带置信区间的预测结果。

### S4 关键技术演示（7:00–9:00，约 560 字）

**镜头 4.1（7:00–7:35）两阶段个性化建模**
【画面】PPT：TCN 结构图（膨胀因果卷积）+ 修正器输入输出示意；可穿插三阶段页曲线
【逐字稿】
核心技术一：两阶段个性化联邦建模。全局 TCN 严格遵循因果卷积网络标准实现——权重归一化、因果填充、膨胀卷积堆叠，感受野完整覆盖三天输入窗口，三十分钟粒度、预测未来三小时。残差修正器以全局预测和历史残差为输入，用分位数损失训练出 P10、P50、P90 三分位修正，梯度从不回传全局模型——个性化能力留在本地，全局知识多方共享。

**镜头 4.2（7:35–8:15）差分隐私实现**
【画面】PPT：DP-SGD 流程图（逐样本梯度→裁剪→加噪→上传）；穿插大屏"每客户端累计 ε"曲线与"自适应裁剪阈值 C"曲线特写
【逐字稿】
核心技术二：客户端侧差分隐私。每个参与方在本地对逐样本梯度做 L2 裁剪，再加高斯噪声后才上传；系统还按各参与方的数据规模定制各自的噪声参数，让大、小数据方消耗相同的隐私预算——隐私面前人人平等。隐私损失用隐私损失分布会计方法逐轮精确追踪：ε 不是一个口头承诺，而是大屏上这条可审计、可复核的曲线。

**镜头 4.3（8:15–8:40）智能体编排**
【画面】PPT 或 agent 控制页：采集→校验→训练→本地修正→预测 流水线一图；闪现单仓库多客户端目录（stage_*/rc_work_*）
【逐字稿】
核心技术三：全流程智能体编排。客户端代理把"采集—校验—训练—本地修正—预测"编排为自动流水线，一条命令启动；同一台机器可并存多个客户端，状态相互隔离；服务端把联邦训练调度为独立工作进程，异常自动回收。非算法人员也能三步接入联邦网络。

**镜头 4.4（8:40–9:00）安全机制清单**
【画面】PPT：安全机制清单页（逐条高亮）
【逐字稿】
贯穿始终的安全机制：JWT 认证与 bcrypt 口令散列；一次性任务密钥仅存 SHA-256；服务器不落盘任何模型参数；原始数据与本地特征全程不出域。

## 4. 备选镜头（按需插入）

- **实现证据闪现**（约 20s，"真系统"背书，可并进 S3 开场或 S4.4）：①仓库结构一闪（fl_code / server / app / web 四目录）；②DP-SGD 核心片段一闪（`fl_code/fed_core/client_core.py` 逐样本裁剪 + 高斯加噪几行，**不逐行讲**）。与下方"审计库特写"构成三件套。榜题不要求视频讲代码，代码走读不进正片。
- **强制停止训练**（约 20s，"可控"加分）：管理端对训练中任务点"强制停止训练" → 状态变"已停止"。话术："管理端具备强制干预能力，可一键终止训练进程并释放资源，任务状态如实复位。"
- **审计库特写**（约 15s）：`data/fl_server.db` 的 audit_rounds 表（DB Browser 打开）：expected/joined/dropped/loss/clip_norm/client_epsilons 逐列指过。话术："每一轮的参与、损失、裁剪与预算全部落库，第三方可离线复核——这就是可溯可审计。"
- **单仓库多客户端**（约 15s）：同一台机器两个 agent 窗口并排（9001/9002），互不串数据。话术："同一台机器可并存多个参与方，状态按客户端严格隔离。"
- **成员推断攻击对照**（⚠️ 慎用）：如评委追问隐私强度的实证，口径为："我们同时做了黑盒成员推断攻击评估，开启差分隐私后攻击者相对无隐私基线没有获得显著优势，并按时序漂移基线做了对照校正——形式化保证与攻击面评估双重验证。"（不要说"泄露率下降 X%"，实测 AUC 差异在 ±2% 内且有漂移混淆。）

## 5. 红线（不能说的话）

1. ❌ "区块链存证 / DID 数字身份已实现" —— 代码中没有，评审一问即穿。话术锚点：榜题原文"**通过但不限于**"、"去中心化或**联邦式**的可信数据空间架构"，我们以联邦架构 + 隐私计算 + 审计链路覆盖"可溯可审计"目标。
2. ❌ "覆盖率达到 80% 名义水平" —— 实测 71–77%，说"接近名义水平、随 ε 稳定"。
3. ❌ "隐私泄露率降低 X%" —— 无可靠实证数字；隐私强度主打 DP 形式化保证 + 逐客户端 ε 计量曲线。
4. ❌ "大模型/LLM 驱动" —— 系统的 Agent 指流程编排智能体，与 LLM 无关，别蹭。
5. ❌ 任何"已在国内电网落地/试点"表述 —— 全部为仿真数据源 + 实验网络。

## 6. 榜题"演示材料"要求对照（2026-09-09 结论）

> 榜题：演示视频需清晰展示**核心功能实现、关键技术演示、性能测试过程及结果**。三类内容的呈现策略：

| 榜题要求 | 结论 | 视频落点 |
|---|---|---|
| 核心功能实现 | **不要求讲代码**（源代码属"技术实现材料"交付物，由材料完整性核查）；需要"实现在场"证据 | S3 真机实况为主体 + "实现证据闪现"镜头（§4） |
| 关键技术演示 | Web App **正式联邦实况就是主体**（真实网络、真实 flwr 通信）；DP 的技术存在感靠大屏**自适应裁剪 C 曲线**与**每客户端累计 ε 曲线**特写 | S3 全程 + S4.2 特写 |
| 性能测试过程及结果 | **允许使用离线全量结果**：榜题明文允许"虚拟仿真系统"作为验证基础，ε 扫描是真实实验非编造；但须满足下方三条件 | S5 全段 |

性能测试三条件：

1. **必须有"过程"画面**——评委看的是测试过程及结果。sweep 全量若未录屏，按镜头 5.1 的补录指引现场实跑分钟级评估脚本，静态图片不能充当"过程"。
2. **口径诚实**——数据来源说"公开数据集/仿真数据源"；覆盖率说"接近名义水平"；MIA 不报"泄露率下降 X%"（见 §4/§5）。
3. **规模口径对齐**——实况（2~3 客户端缩小配置）与性能数字（9 参与方 30 轮全量）是两条线，S3.1 与 S5.1 已分别交代，避免评委疑惑两边客户端数不一致。
