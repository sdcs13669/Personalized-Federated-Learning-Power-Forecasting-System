# 数据清洗脚本演进总结

> 面向大一同学：通过对比两版清洗代码，理解时序预测数据清洗的关键设计决策和演进逻辑。

## 0. 背景

个性化联邦学习 + 差分隐私的电力负荷预测系统中，数据清洗是实现联邦学习的第一道防线——必须逐客户端独立清洗，防止跨用户信息泄漏。

原始提交 `35190cc`（4 份脚本，`data/manifests/`）→ 当前版本 `main`（5 份脚本，`data/scripts/clean-feature-engneer/`）。

| 维度 | 原始版（35190cc） | 当前版（main） |

## 2. 为什么做这些改动

### 2.1 MAD → IQR

**原始版**用 MAD 的鲁棒 Z-score：`z = 0.6745*(x - median)/MAD`，系数 c 取 3。

**问题**：电力数据右偏严重——大部分时间低负荷，偶尔高负荷高峰。MAD 基于 median，右侧高峰若占比大，MAD 被拉高，检测灵敏度下降。IQR 基于分位数，对偏态分布更稳健。

**当前版**：标签用 **diff IQR**（一阶差分上做 IQR，检测突变尖峰）；特征用 **rolling IQR**（336 步 = 7 天居中滑动窗口，检测相对局部模式的偏离）。系数统一 2.5。

```
diff IQR    : d = s.diff() → lo,hi = Q1(d) ± 2.5×IQR(d) → |d| > bound → NaN
rolling IQR : 当前点居中取 336 点窗口 → lo,hi = Q1(win) ± 2.5×IQR(win) → 超出 → NaN
```

**为什么标签不用 rolling IQR？**

diff IQR 和 rolling IQR 检测的是不同类型的问题，所以分工不同：

| 方法 | 检测目标 | 适用对象 | 典型异常 |
|------|---------|---------|---------|
| diff IQR | 物理上不可能的变化速率 | 标签（功率负荷） | 传感器跳变：30 分钟内从 50kW 飙到 500kW 再回落 |
| rolling IQR | 相对局部模式的偏离 | 特征（天气、电压、CO2 等） | 传感器漂移：某 CO2 读数在 7 天窗口中突然翻倍 |

电力负荷本身就有巨大的日内和周内波动（晚间高峰可能是凌晨低谷的 3-5 倍），如果对标签使用 rolling IQR，正常的用电高峰和低谷会被当成异常标记掉——因为相对于 7 天窗口的中位数，高峰"看起来很高"，低谷"看起来很低"，但它们实际上是正常的负荷模式。

diff IQR 看的是**变化速率**而非**绝对值**。无论负荷处于高峰还是低谷，相邻两点的差应该在一个合理范围内。如果出现物理上不可能的大跳变（30 分钟 100kW+ 的瞬时突变），那一定是传感器或传输错误。

特征则不同——CO2、温度、电压等变量本身变化范围不大，不会像负荷那样有剧烈的日内波动，所以 rolling IQR 适合检测它们相对局部模式的偏离。

### 2.2 前导零截断

**问题**：变压器/电表安装前，原始数据全是 0。这些 0 不是"零负荷"，而是"未接入"。如果不截断：
- 全序列的 IQR 统计被大量 0 拉偏
- gap 检测把"安装前"误判为"数据中断"

**当前版**：每列/每户找第一个 >0 的值，之前全部置 NaN（或删行）。

### 2.3 双重 gap 过滤

```
过滤1（插值前，raw gap）  : 原始数据中 zero/NaN 连续 > MAX_GAP_DROP → 丢弃
过滤2（插值前，post gap） : 异常标记后 NaN 连续 > MAX_GAP_DROP → 丢弃
插值（最后）              : gap 合格 → 三次样条填补
```

**为什么要两次**：过滤1 针对原始数据质量（传感器长期故障）；过滤2 针对异常检测后的累积 NaN（大量相邻点都被 IQR 标记）。

**为什么插值放在最后**：先判断 gap 是否值得保留，再填补。如果先插值再过滤，大 gap 被强行填了，过滤就失效了。

### 2.4 线性插值 → 三次样条

**原始版**：`s.interpolate(method="linear", limit=6)` —— 用前后两点连直线，最多填 6 步。

**当前版**：`s.interpolate(method="cubic", limit_area="inside")` —— 三次样条拟合整段曲线的曲率，不设 limit（gap > MAX_GAP_DROP 的已在过滤2 丢弃）。

三次样条比线性插值更贴合电力负荷的连续变化特性——负荷不会在两采样点间直线跳变。

`limit_area="inside"`：只填两端都有有效值的内部缺口，前导/尾随 NaN 不填。

### 2.5 插值后 clip

三次样条在接近 0 的区域可能振荡产生负值。插值后重新 `clip(物理下界, +∞)` 确保数据不违反物理约束。

### 2.6 路径修复

```
原始：ROOT = parents[1] = data/
      RAW  = data/data/raw/...   ← 路径重复
当前：ROOT = parents[2] = repo/
      RAW  = repo/data/raw/...   ← 正确
```

### 2.7 steel 特征漏检修复

**原始版**只对 `Usage_kWh`（标签）做了异常检测，5 个本地特征完全跳过。CO2 传感器故障或无功功率突变会原样进入 processed。

**当前版**：标签用 `detect_outliers_diff`，特征用 `detect_outliers_rolling`，统一经过 `clean_column`。

### 2.8 输入格式统一化

`eld_ind` 和 `household_res` 原始数据为 `.txt`（分号分隔，逗号小数等非标准格式）。先转为标准 `.csv`，脚本只读 `.csv`，去除 `sep=";"`、`decimal=","` 等特例处理。

## 3. 当前统一流水线

```
                         加载 CSV
                            │
                    重采样到 30min (mean)
                            │
              ┌─[过滤1: raw gap > MAX_GAP_DROP?]──Yes──▶ 丢弃
              │             │ No
              │    截断前导零 → NaN
              │             │
              │   ┌─ 标签: diff IQR (系数 2.5)
              │   ├─ 特征: rolling IQR (window=336, center=True)
              │   └─ 标记异常 → NaN → clip(物理下界, +∞)
              │             │
              └─[过滤2: post gap > MAX_GAP_DROP?]──Yes──▶ 丢弃
                            │ No
               三次样条插值 (cubic, limit_area="inside")
                            │
                     clip(物理下界, +∞)
                            │
                    添加公共时间特征 (8 维)
                            │
                        输出 CSV
```

## 4. 各数据集参数差异

| 参数 | eld_ind | lcl_res | steel_ind | tetouan_city | household_res |
|------|:--:|:--:|:--:|:--:|:--:|
| 原生步长 | 15min | 30min | 15min | 10min | 1min |
| MAX_GAP_DROP | 48 | 48 | 48 | **72** | **336** |
| IQR_MULTIPLIER | 2.5 | 2.5 | 2.5 | 2.5 | 2.5 |
| 异常检测类型 | diff IQR | diff IQR | diff + rolling | diff + rolling | diff + rolling |
| 处理方式 | numpy 向量化 | 逐户 batch | 逐列 Series | 逐列 Series | 逐列 Series |
| category_id | 1 | 0 | 2 | 1 | 0 |

`MAX_GAP_DROP` 差异理由：
- **48**（默认）：1 天空白即丢弃，适合数据质量好的数据集
- **72**（tetouan）：wind_speed 有 62 步 gap（31h），放宽到 72 保留该特征
- **336**（household）：单户 4 年数据中有约 5 天自然空白，按 7 天阈值保留

## 5. 大一同学需要记住的关键原则

1. **原始数据永不动**——清洗必须通过脚本复现，禁止手工改数
2. **逐客户端独立**——归一化、缺失填充、异常检测都不能跨客户端借用信息（联邦学习防泄漏）
3. **先过滤，再插值**——判断序列是否可接受 → 丢弃不可接受的 → 对保留的填补
4. **插值后必须 clip**——三次样条等非线性插值可能振荡出界
5. **阈值按数据特性定**——不要照搬数字，先看数据的分布、缺失率、gap 分布再决定
6. **输出要清晰**——打印区分数据列 vs 公共特征列，便于后续建模确认维度
