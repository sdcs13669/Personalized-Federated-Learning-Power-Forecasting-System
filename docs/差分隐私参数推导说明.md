# 差分隐私参数计算过程与原理说明

Date: 2026-08-15

本文档解释 `fl_code/train_baseline.py` 中 DP-FedAvg 三个参数
（`--dp-noise` σ、`--dp-clip` C、`--dp-delta` δ）的计算依据，
以及隐私预算 ε 的完整推导过程。所有数值均可通过
`_compute_epsilon()`（train_baseline.py，基于 Opacus RDPAccountant）
复现。

## 0. 目标与约定

- 隐私预算控制目标（主方案文档）：**ε ≤ 8，δ = 10⁻⁵**
- 采样率 q = 1.0：全部客户端每轮参与，无采样放大
- DP 层级：**客户端本地加噪**（local DP 风格）——每个客户端在本地上传前
  对自己的更新做固定裁剪 + 高斯加噪，服务器只做聚合（后处理），
  即使服务器不可信也无法还原任何客户端的真实更新

## 1. (ε, δ)-差分隐私定义

机制 M 满足 (ε, δ)-DP，当对任意相邻数据集 D、D'（差一条记录）和
任意输出集 S：

```
Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S] + δ
```

- ε：隐私损失上界，越小越私密
- δ：违反 ε 保证的最大允许概率（本项目 δ = 10⁻⁵）

## 2. 客户端本地机制与灵敏度（为什么 ε 与 C 无关）

DP-FedAvg 每轮流程（隐私操作全部在客户端本地完成）：

1. 客户端 i 下载全局模型 θ_global，本地训练得到 θᵢ
2. 本地计算更新：Δᵢ = θᵢ − θ_global
3. 本地裁剪：`clip(Δᵢ, C) = Δᵢ · min(1, C/‖Δᵢ‖₂)`，
   强制 ‖clip(Δᵢ)‖₂ ≤ C（所有参数拼接后按全局 l2 范数裁剪）
4. 本地加噪后上传：Δ̃ᵢ = clip(Δᵢ) + N(0, (σC)²I)
5. 服务器仅做聚合（后处理）：θ_new = θ_global + Σ wᵢ·Δ̃ᵢ
   （wᵢ 为 FedAvg 权重，Σwᵢ = 1）

**灵敏度推导（客户端级相邻分析）**：对客户端 i 的数据做相邻分析，
聚合输出 = Σⱼ wⱼ·clip(Δⱼ) + Σⱼ wⱼ·Nⱼ(0, σ²C²I)。改变客户端 i 的数据
最多使 clip(Δᵢ) 变化 C（l2 范数）→ 输出的灵敏度 = wᵢ·C。其他客户端的
噪声 Nⱼ 在相邻数据集下是常数、不提供保护；有效随机性仅来自 Nᵢ，
噪声标准差 = wᵢ·σC。故 **noise multiplier = wᵢσC / (wᵢC) = σ**，
与聚合权重 wᵢ 无关。

结论：**ε 只由 σ、轮数 T、采样率 q、δ 决定，与 C 无关**
（灵敏度和噪声同乘 C，相互抵消），也与聚合加权方式无关。
C 只影响裁剪偏置（精度），是独立于隐私的精度旋钮。

注：客户端本地加噪下，聚合模型的噪声总量为 σC·√(Σwᵢ²)
（等权时 σC/√n），比服务器端加噪（σC/n）大 √n 倍——这是
"服务器不可信"威胁模型下本地 DP 的固有代价：每个客户端都必须
独立保护自己的数据。

## 3. 高斯机制的 RDP（每轮）

Rényi 差分隐私：机制 M 满足 (α, ε_RDP)-RDP，当 α 阶 Rényi 散度
D_α(M(D) ‖ M(D')) ≤ ε_RDP。

对灵敏度 Δ、噪声 std σΔ 的高斯机制（即 noise multiplier σ），
RDP 有闭式解：

```
ε_RDP(α) = α / (2σ²)
```

本项目 q = 1.0（无采样），每轮直接套用上式：
每轮 ε_RDP(α) = α / (2σ²)。

## 4. 组合定理（T 轮线性相加）

RDP 对组合可加：

```
ε_RDP(α) = T · α / (2σ²)
```

σ = 4.0、T = 30：ε_RDP(α) = 30α / 32 = 0.9375α。

## 5. RDP → (ε, δ) 转换（Balle et al. 2020 定理 21）

Opacus 采用 Balle《Hypothesis testing interpretations and Rényi
differential privacy》(AISTATS 2020) 定理 21 的紧化转换。
对每个 α > 1 给出一个可行 (ε, δ) 对：

```
ε(α) = ε_RDP(α) − (ln δ + ln α)/(α − 1) + ln((α − 1)/α)
```

取所有 α 中的最小值：

```
ε* = min_{α>1} ε(α)
```

注意：教科书版 `ε_RDP − ln(δ)/(α−1)` 缺少
`−ln α/(α−1) + ln((α−1)/α)` 两项，界更松，手算结果会大于
Opacus 输出，属于正常现象。

## 6. 数值代入（σ = 4.0，T = 30，δ = 10⁻⁵）

```
ln δ = −11.5129

每轮 RDP(α) = α / (2·16) = α/32
30 轮 RDP(α) = 0.9375α

最优 α* = 4.3（Opacus α 网格搜索）

ε(4.3) = 0.9375 × 4.3  −  (−11.5129 + ln 4.3)/(4.3 − 1)  +  ln(3.3/4.3)
       = 4.03125        −  (−11.5129 + 1.4586)/3.3        +  (−0.2647)
       = 4.03125        +  3.0468                          −  0.2647
       = 6.8133
```

与脚本打印的 `ε=6.81` 一致。Opacus 的 α 网格
（`RDPAccountant.DEFAULT_ALPHAS`）为 1.1~10.9（步长 0.1）+ 12~63。

## 7. 参数对照表与推荐配置

同一计算对 σ = 3.0 / 3.5 重复（每轮 RDP = α/(2σ²)，其余不变）：

| σ | 每轮 RDP(α) | 最优 α* | ε（30 轮） | 是否满足 ε ≤ 8 |
|---|-------------|---------|------------|----------------|
| 3.0 | α/18 | 3.5 | 9.60 | ✗ 超预算 |
| 3.5 | α/24.5 | 3.9 | 7.98 | ✓ |
| 4.0 | α/32 | 4.3 | 6.81 | ✓（留余量） |

20 轮（默认轮数）对照：

| σ | ε（20 轮） | 是否满足 ε ≤ 8 |
|---|------------|----------------|
| 2.5 | 9.37 | ✗ 超预算 |
| 3.0 | 7.53 | ✓ |

推荐命令：

```bash
# 20 轮，ε≈7.5
python -m fl_code.train_baseline --dp-noise 3.0 --dp-clip 1.0 --dp-delta 1e-5

# 30 轮，ε≈6.8
python -m fl_code.train_baseline --rounds 30 --dp-noise 4.0 --dp-delta 1e-5
```

- σ 是隐私旋钮：ε 随 σ 增大而减小（约按 1/σ² 比例）
- ε 随轮数近似线性增长：轮数翻倍时 σ 需放大 √2 倍才能维持同等 ε
- C 是精度旋钮：默认 1.0；若 DP 后 MAE 退化明显可调至 2.0~5.0
  （减少裁剪偏置），σ 不变则 ε 不变；调大 `--lr`/`--epochs` 时
  本地更新范数变大，C 需相应上调
- 训练启动时脚本会打印本轮预算对应的 ε，微调 σ 后重跑即可校准

## 8. 原理一句话总结

每轮每个客户端在本地对自己的更新做高斯加噪（灵敏度 C、噪声 std σC，
乘子 σ），服务器聚合为后处理；该机制在 Rényi 散度下每轮贡献 α/(2σ²)，
T 轮线性相加后经 Balle 定理 21 转换、对 α 取最小，即得隐私预算 ε；
给定目标 ε 与 δ 即可反解出所需 σ。
