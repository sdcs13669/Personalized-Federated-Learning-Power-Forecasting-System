# 数据清洗规范

> 版本：v1.0
> 适用范围：个性化联邦学习 + 差分隐私的电力负荷预测系统 —— 开源数据收集阶段
> 目标读者：项目全体成员（含大一新成员）
> 关联文档：《数据采集.md》（选数据集、raw 存放、manifest）

---

## 0. 原则

> **原始数据永不修改，清洗过程必须可复现，每一份进入训练的数据都必须有质量报告。**
> 清洗方法与阈值不写死，**根据具体数据集的特性选择**（见第 2 节），本规范提供框架与默认规则。

---

## 1. 目标与适用范围

本规范规定了 raw → processed 的清洗全流程：

1. 清洗前如何**分析数据特性并制定清洗方案**（这是本规范的核心，先看数据再定方法）；
2. 清洗的**标准流程**（含异常值清洗与特征筛选）；

本规范不涉及模型训练、联邦聚合与差分隐私加噪（那是后续阶段的事），
但所有清洗规则都遵循一条底线：**不引入跨客户端的数据泄漏**（见第 8 节）。

> 铁律：**先复制到 raw 再清洗，raw 永远不动；所有改动用脚本完成并留档，禁止手工改数。**

---

## 2. 清洗前的准备：数据特征分析与清洗方案设计

清洗方法取决于**找到的数据是什么样**。每个数据集在清洗前，先回答下表问题
（答案来自 manifest 与对 raw 数据的探查，即 EDA），再据此选择各步方法。

| 特征项     | 需确认内容                           | 影响的清洗步骤                 |
| ---------- | ------------------------------------ | ------------------------------ |
| 原生分辨率 | 采样间隔、是否均匀                   | §3 统一 timestep:30min        |
| 单位       | 功率单位是否 kW、时间戳格式          | §4.1 基础处理                 |
| 缺失表达   | 空 / NaN / 0 / 无记录，用哪种表示    | §4.2 缺失值处理               |
| 负值语义   | 是否有分布式光伏并网（净计量）       | §4.3 异常值处理               |
| 序列语义   | 每条序列代表什么（家庭/工厂/产线…） | 客户端划分（后续建模阶段决定） |

## 4. 数据清洗

### 4.1 基础处理（加载与时间戳）

- 脚本读取，核对列名/类型/行数与 manifest 一致；
- 统一时间戳。

### 4.2 缺失值处理

处理缺失值的常见方法：

- **均值/中位数填充**：用附近数据的均值或中位数填补，简单但会削弱波动，适合缺失占比很低时；
- **前向/后向填充**：用上一个或下一个有效值填充，适合短暂中断；
- **线性插值**：用前后两点插值，适合小范围缺失（几个采样点以内），推荐优先使用。

### 4.3 异常值处理

先做**物理界检查**：明显超出物理可能范围的值（如负功率、超容量）直接判为异常。

再按两类方法判断：

**统计方法（单点判断）**：

- **对 输数据集入特征 箱线图 / IQR 四分位法**：以 `[Q1 − 1.5×IQR, Q3 + 1.5×IQR]` 为正常区间，区间外为异常；IQR=|Q3-Q1|
- **MAD 的鲁棒 Z-score**：`|z| > c` 判异常；用 MAD 的鲁棒 Z 对异常数据更稳健。C一般为2.5~3.5（公式见附录 B）。

**时序特有方法（利用前后关系）**：

- **差分突变检测**：对相邻点做差分，差分值远超局部波动的点判为尖峰突变；
- **时间间隔异常**：相邻采样时间间隔明显大于正常间隔，提示该段数据不连续或缺失；
- **孤立森林**：基于"隔离异常点"的无监督方法，适合多维特征场景。

处置默认做法：孤立异常点用插值覆盖；连续成段的异常整段置 NaN（按缺失处理）；越界值截断到物理边界；处置依据记录到质量报告。

### 4.4 输出

写 `data/processed/<数据集ID>.csv` 和 `<数据集ID>.yaml`（清洗与质量报告，格式见 §7），清理脚本在 `scripts/` 目录。

## 5. 特征工程（公共特征与本地特征划分）

> 本节在清洗后执行，将各数据集的原始列划分为公共特征（encoder 输入）和本地特征（head 输入）。
> 划分依据：《个性化模型设计.md》§3 特征分工——公共特征参与联邦聚合，本地特征永不上传。

### 5.1 特征一览（所有客户端统一）

从时间戳和目标列派生。下表声明每个特征供 encoder 还是 head（本地头）使用：

| 特征名          | 类型  | 使用者  | 编码/来源                 | 说明                   |
| --------------- | ----- | ------- | ------------------------- | ---------------------- |
| `hour_sin`    | float | encoder | sin(2π × hour / 24)     | 日周期（正弦）         |
| `hour_cos`    | float | encoder | cos(2π × hour / 24)     | 日周期（余弦）         |
| `dow_sin`     | float | encoder | sin(2π × dayofweek / 7) | 周周期（正弦），周一=0 |
| `dow_cos`     | float | encoder | cos(2π × dayofweek / 7) | 周周期（余弦）         |
| `is_weekend`  | int   | encoder | 周六/日=1，其余=0         | 周末标志               |
| `month_sin`   | float | encoder | sin(2π × month / 12)    | 年周期（正弦），1月=0  |
| `month_cos`   | float | encoder | cos(2π × month / 12)    | 年周期（余弦）         |
| `category_id` | int   | encoder | 0=居民，1=变压器，2=工业  | 负荷类别               |
| `lag_t-1`     | float | head    | 目标列 shift 1 步         | 前一时刻（30min前）    |
| `lag_t-2`     | float | head    | 目标列 shift 2 步         | 前两时刻（1h前）       |
| `lag_t-48`    | float | head    | 目标列 shift 48 步        | 前一天同时刻           |
| `lag_t-168`   | float | head    | 目标列 shift 168 步       | 前3.5天同星期时刻      |

说明：

- encoder 输入维度：**8**（7 个时间派生 + 1 个类别），所有 客户端一致，保证 TCN encoder 的 `in_channels` 统一；
- 滞后值（lag）不进 encoder——TCN 的因果卷积已覆盖短期自相关，滞后值作为 head 的朴素基线，让 head 只需学 encoder 输出与目标之间的残差；
- `category_id` 使单一 encoder 能区分不同负荷类型的时序模式；
- 循环特征使用 sin/cos 成对编码，避免 23→0 跳变和对称时间点混淆；
- 时间派生和 category_id 写入 `processed`；lag 在建模脚本中按客户端独立构造，不进 `processed`。

### 5.2 本地特征（按数据集）

本地特征是数据集原生的物理量，仅作为本地 head 的附加输入。本地 head 同时接收 encoder 输出（flatten）和本地特征。

| —   | 无本地特征 |

按客户端划分（见《客户端数据划分方案.md》§2.4），每个 Zone 客户端仅保留对应 Zone 的功率列作为目标，其余两个 Zone 的功率列不作为本地特征（避免跨客户端信息泄漏）。

本地特征维度 = **5**。

### 5.3 特征维度汇总

| 数据源       | encoder 输入 | 本地特征 | head lag 输入 | head 总输入        |
| ------------ | ------------ | -------- | ------------- | ------------------ |
| eld_ind      | 8            | 0        | 4             | 64 × seq_len + 4  |
| lcl_res      | 8            | 1        | 4             | 64 × seq_len + 5  |
| steel_ind    | 8            | 6        | 4             | 64 × seq_len + 10 |
| tetouan_city | 8            | 5        | 4             | 64 × seq_len + 9  |

- encoder 输入 = 8（时间派生 7 + category_id 1），所有 客户端一致；
- head 总输入 = encoder 输出（64 × seq_len）+ 本地特征（0~6）+ lag（4）。

## 6. 特征筛选

先区分两个概念：

- **特征工程**（§5）：由现有列派生时间特征，按公共/本地划分，写入清洗脚本，进入 processed；
- **特征筛选**（本步）：对 §5 定义的本地特征列做质量过滤，决定最终保留哪些。

筛选方法按类别介绍：

### 6.1 统计筛选（不依赖模型）

- **相关性分析**：与功率目标相关系数过高的冗余列考虑去重；
- **多重共线性（VIF）**：VIF > 10 时剔除之一（公式见附录 B）；
- **互信息**：能捕捉非线性关系的相关性度量，比 Pearson 更灵活。

### 6.2 模型筛选（嵌入式）

- **XGBoost + SHAP（本项目推荐）**：先训练 XGBoost 得到特征重要性，再用 SHAP 值看每个特征对预测的贡献方向与量级，解释性强；

### 6.3 注意

- 筛选规则要保守（宁留勿删，防止丢失个性化信息）；
- 筛选与后续建模都应基于各自客户端的数据做，避免跨客户端统计造成泄漏（见第 8 节）。

## 7. 清洗与质量报告（YAML 格式）

每数据集清洗完成后，在 `data/processed/<dataset_id>.yaml` 输出一份结构化报告。
清洗前填写 `data_profile` 和 `cleaning_plan`，清洗后填写 `quality_metrics`。

### 7.1 文件模板

```yaml
# <dataset_id> 清洗方案与质量报告
meta:
  dataset_id:      <string>   # 与 manifest 一致
  submitted_by:    <string>
  reviewer:        <string>
  date:            <date>     # YYYY-MM-DD
  script:          <path>     # scripts/clean_<dataset_id>.py

# ---- 清洗前：数据特征分析与方案 ----
data_profile:
  native_timestep:       <int>    # 秒，如 900
  uniform:               <bool>   # 采样间隔是否均匀
  unit_power:            <string> # kW / W / kWh
  timestamp_format:      <string> # "yyyy-mm-dd hh:mm:ss"
  missing_format:        <string> # NaN / 0 / "?" / 空
  negative_semantics:    <string> # "无" / "光伏净计量"
  sequence_semantics:    <string> # "单户家庭" / "中压变压器" / "工厂"

cleaning_plan:
  target_timestep:       <int>    # 秒，统一目标 1800 (30min)
  resample_method:       <string> # mean / sum
  missing:
    method:              <string> # linear_interp / forward_fill / drop / none
    max_gap:             <int>    # 大缺口阈值(步数)，超过保留 NaN
  outlier:
    physical_bounds:     [<float>, <float>]  # [min, max]
    statistical:         <string> # IQR / MAD_Z / none
    temporal:            <string> # diff_outlier / isolation_forest / none
  features:
    drop_columns:        [<string>]  # 原始列中舍弃的（含理由）
    retain_columns:      [<string>]  # 保留为本地特征的原始列
  plan_reviewed:         <bool>

# ---- 清洗后：质量指标 ----
quality_metrics:
  missing_rate:          <float>  # 0.0 ~ 1.0
  max_gap_steps:         <int>    # 最长连续缺失间隔（统一 timestep 后的步数）
  outlier_ratio:         <float>  # 判为异常的样本占比
  value_range_after:     [<float>, <float>]  # 清洗后 [min, max]
  residual_risks:        <string> # 残余风险说明
```

### 7.2 字段约束

| 字段                                      | 约束                                                             |
| ----------------------------------------- | ---------------------------------------------------------------- |
| `meta.dataset_id`                       | 与 `data/manifests/<dataset_id>.yaml` 中的 `dataset_id` 一致 |
| `data_profile.*`                        | 来自对 raw 数据的探查（EDA），清洗前填写                         |
| `cleaning_plan.target_timestep`         | 统一为 1800（30 min），遵循 §3 规则                             |
| `cleaning_plan.missing.max_gap`         | 超过此阈值的连续缺失段保留 NaN，不填充                           |
| `cleaning_plan.outlier.physical_bounds` | 根据物理常识设定，如功率 [0, 容量上限]                           |
| `cleaning_plan.features.drop_columns`   | 注明舍弃理由（如被公共特征覆盖、缺失率过高）                     |
| `quality_metrics.missing_rate`          | 清洗**后**的缺失率（含重采样产生的 NaN）                   |
| `quality_metrics.max_gap_steps`         | 清洗**后**的最大连续 NaN 段长度                            |
| `quality_metrics.value_range_after`     | 异常值处置后的值域，用于核对物理界                               |
| `quality_metrics.residual_risks`        | 已知但未处理的残余问题（如夏令时、大缺口段）                     |

### 7.3 示例（eld_ind 清洗方案片段）

```yaml
meta:
  dataset_id: "eld_ind"
  submitted_by: "xxx"
  date: "2026-08-10"

data_profile:
  native_timestep: 900
  uniform: true
  unit_power: "kW"
  timestamp_format: "yyyy-mm-dd hh:mm:ss"
  missing_format: "0 (接入前)/NaN"
  negative_semantics: "无"
  sequence_semantics: "中压变压器负荷"

cleaning_plan:
  target_timestep: 1800
  resample_method: "mean"
  missing:
    method: "linear_interp"
    max_gap: 6
  outlier:
    physical_bounds: [0, 10000]
    statistical: "MAD_Z"
    temporal: "diff_outlier"
  features:
    drop_columns: []
    retain_columns: []
  plan_reviewed: false

quality_metrics:
  missing_rate: 0.003
  max_gap_steps: 2
  outlier_ratio: 0.008
  value_range_after: [0, 8750]
  residual_risks: "夏令时切换日 1:00-2:00 值异常，保留 NaN"
```

## 8. 面向联邦学习与差分隐私的约束（防泄漏）

1. **归一化/缩放必须按客户端各自计算**：每个客户端用自己的统计量（如各自 min-max），禁止用全数据集或跨客户端的统计量。否则会把客户 A 的信息泄漏给客户 B。
2. **清洗不得跨客户端借用信息**：一个客户的缺失值只能用该客户自身的数据填补。
3. **差分隐私与噪声加在哪里**：差分隐私在训练/聚合阶段对梯度或查询结果加噪，**不在清洗阶段**。清洗阶段不要为了"看起来更平滑"而做会放大噪声敏感度的操作。
4. **个性化语义记录**：客户端划分与理由必须写入 manifest，这是后续个性化建模（按类别 res/ind、按客户端局部微调）的数据依据。
5. **数据版本**：processed 数据一旦入库即视为只读；任何清洗规则变更需新增清洗脚本版本并重跑全流程，禁止在原文件上改。

## 附录 A：常用公式

- IQR：`IQR = Q3 − Q1`，离群区间 `[Q1 − 1.5·IQR, Q3 + 1.5·IQR]`
- 鲁棒 Z 分数：`z = 0.6745 · (x − median) / MAD`，`MAD = median(|x_i − median|)`
- 一阶差分（差分突变检测）：`Δx_t = x_t − x_{t−1}`，差分绝对值远超局部波动的点判为突变
- 缺失率：`missing_rate = #NaN / N`
- 相关系数（Pearson）：`r = cov(x,y) / (σ_x σ_y)`
- 互信息：`MI(X;Y) = Σ_x Σ_y p(x,y) log(p(x,y) / (p(x)p(y)))`，衡量非线性相关
- 方差膨胀因子：`VIF = 1 / (1 − R²)`，其中 R² 是某特征对其它特征回归的判定系数；`VIF > 10` 视为强共线性

*本规范为 v1.0，随具体数据特征与清洗实践修订（例如：遇到新型缺失表达、需要新增物理界阈值时，更新对应章节并登记版本号）。*
