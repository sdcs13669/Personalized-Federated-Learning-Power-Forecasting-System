# 客户端数据划分方案

> 版本：v2.0
> 更新：2026-08-10（基于清洗后实际数据修订，快速实验方案）
> 适用范围：个性化联邦学习实验的客户端定义与数据划分
> 目标读者：项目全体成员

---

## 1. 总体原则

- 单一共享 TCN encoder + 本地个性化 MLP head
- 类别信息通过**类别特征编码**注入 encoder（0=居民，1=变压器，2=钢铁工业）
- encoder 聚合采用标准 **FedAvg 按数据量加权**
- 数据集划分严格按时间顺序（不 shuffle）
- 划分比例：**80% 训练 / 20% 测试**（不设验证集，直接训练/测试划分）

---

## 2. 客户端划分

**快速实验方案：9 个客户端**（减少通信轮次，加快迭代速度）。完整 72 客户端方案见 v1.2 历史版本。

| 数据源       | 客户端数 | 划分规则                     | 类别特征    | 本地特征维度 |
| ------------ | -------- | ---------------------------- | ----------- | ------------ |
| eld_ind      | 3        | 按有效天数分档               | 1（变压器） | 0            |
| lcl_res      | 2        | 按有效天数分档（730天为界）  | 0（居民）   | 0            |
| steel_ind    | 1        | 整个数据集                   | 2（工业）   | 4            |
| tetouan_city | 3        | 1 个分区/客户端              | 0 / 2       | 5            |

**合计：9 个客户端。**

### 2.1 eld_ind — 3 客户端（按有效天数分档）

- 原始 370 个 MT 列，清洗后实得 **361 列**，全部通过连续性检查（内部无 >24h 缺口）
- **过滤**：有效天数 < 365 的 19 个序列直接丢弃（不在任何客户端中）
- 剩余 342 序列按有效天数分为 3 档：

| 客户端      | 有效天数范围  | 序列数 | 说明                |
|------------|-------------|-------|---------------------|
| eld_ind_0  | [365, 730)  | 14    | 短序列（1~2年）      |
| eld_ind_1  | [730, 1095) | 15    | 中等序列（2~3年）    |
| eld_ind_2  | >= 1095     | 313   | 长序列（3年以上）    |

- 每条序列采样间隔 15min，统一重采样到 **30min**（每 2 行取均值）
- 全序列时间跨度：1461 天 @30min（2011-11-23 ~ 2014-02-27），70,129 步
- 单序列有效步数：~37K ~ 70K（mean=60,600），差异来自变压器投运时间不同
- 首尾 NaN 来自变压器投运/退役时间差异，非质量问题

### 2.2 lcl_res — 2 客户端（按有效天数分档）

清洗后 **321 户全部有效**（NaN≤50%），有效步数 23,691 ~ 39,727（mean=36,762）。

| 客户端     | 有效天数    | 序列数 | 说明              |
|-----------|------------|-------|-------------------|
| lcl_res_0 | < 730      | 145   | 短序列（<2年）     |
| lcl_res_1 | >= 730     | 176   | 长序列（≥2年）     |

- 原生采样间隔 30min，**无需重采样**
- **本地特征维度 0**：`tariff_type` 在特征筛选中被剔除（该公开子集全为常量 Std，无 ToU 用户）

### 2.3 steel_ind — 1 客户端

- 整个数据集算 1 个客户端，1 条序列
- 采样间隔 15min，统一重采样到 **30min**（每 2 行取均值）
- 序列长度：17,520 步（365 天 @30min，2018-01-01 ~ 2018-12-31）
- 类别特征：2（钢铁工业）
- **本地特征维度 4**：`lagging_reactive_power`、`co2`、`lagging_pf`、`load_type`
  - 剔除：`leading_reactive_power`（SHAP 0.24，<1%）、`leading_pf`（SHAP 0.21，<1%）

### 2.4 tetouan_city — 3 客户端

- Zone 1（工业区）、Zone 2（居民商业混合）、Zone 3（居民商业）各算 1 个客户端
- 每个客户端 1 条序列
- 采样间隔 10min，统一重采样到 **30min**（每 3 行取均值）
- 序列长度：17,472 步（364 天 @30min，2017-01-01 ~ 2017-12-30）
- 类别特征：Zone 1 → 2（工业），Zone 2、3 → 0（居民）。**注意**：清洗后 csv 的 `category_id` 列为常量 1（错误），建模脚本必须按客户端覆盖
- **本地特征维度 5**：`temperature`、`humidity`、`wind_speed`、`general_diffuse_flow`、`diffuse_flow`

## 3. 数据划分（每序列独立执行）

所有序列按 **8:2** 比例、严格时间顺序切分：

```
|<--- train 80% --->|<-- test 20% -->|
```

- 不设验证集，固定 epoch 训练
- 划分以序列为单位执行（不是以客户端为单位）
- 同客户端内的多条序列各自独立切分
- 不 shuffle，保证时间因果性

---

## 4. FedAvg 聚合权重

按每个客户端的数据量（总有效步数）加权：

| 组                       | 步数占比 | 说明                           |
| ------------------------ | -------- | ------------------------------ |
| 3 个 eld_ind 客户端      | ~72%     | 合计 342 序列，313 条集中在 eld_ind_2 |
| 2 个 lcl_res 客户端      | ~28%     | 合计 321 序列，长档略多         |
| steel_ind + tetouan_city | <0.2%    | 每客户端 1 条序列              |

eld_ind_2（313 序列）在聚合中占主导。steel_ind 和 tetouan_city 权重极低，核心价值在**评估时验证跨域泛化能力**。

## 5. 特征分工

### 5.1 公共特征（Global TCN 输入，8 维）

所有 9 个客户端统一派生，维度与编码见《数据清洗.md》§5.1：

| 特征 | 编码 | 含义 |
|------|------|------|
| hour_sin | sin(2π·hour/24) | 小时正弦 |
| hour_cos | cos(2π·hour/24) | 小时余弦 |
| dow_sin | sin(2π·dow/7) | 星期正弦 |
| dow_cos | cos(2π·dow/7) | 星期余弦 |
| is_weekend | 0/1 | 周末标志 |
| month_sin | sin(2π·(month-1)/12) | 月正弦 |
| month_cos | cos(2π·(month-1)/12) | 月余弦 |
| category_id | 0/1/2 | 类别编码 |

### 5.2 本地特征（Residual Corrector 输入）

特征筛选后各数据集的本地特征（完整筛选依据见 `data/feature_selection/`）：

| 数据源 | 本地特征维度 | 具体列 | 说明 |
|--------|------------|--------|------|
| eld_ind | **0** | — | 无原生非功率列 |
| lcl_res | **0** | — | `tariff_type` 为常量，已剔除 |
| steel_ind | **4** | `lagging_reactive_power`, `co2`, `lagging_pf`, `load_type` | 剔除2列：`leading_reactive_power`(SHAP<1%)、`leading_pf`(SHAP<1%) |
| tetouan_city | **5** | `temperature`, `humidity`, `wind_speed`, `general_diffuse_flow`, `diffuse_flow` | 全保留（VIF<5，物理意义明确） |

各客户端 Corrector 输入维度（输入沿特征维度拼接：`Y_pre` + 近期真实历史 + D_local）：

| 数据源 | Corrector 特征维度 (2 + D_local) |
|--------|--------------------------------|
| eld_ind | 2 + 0 = **2** |
| lcl_res | 2 + 0 = **2** |
| steel_ind | 2 + 4 = **6** |
| tetouan_city | 2 + 5 = **7** |
