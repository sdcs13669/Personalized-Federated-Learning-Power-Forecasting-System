# 差分隐私参数计算过程与原理说明

Date: 2026-08-16（更新：PLD 会计 + 每客户端预算反解 σᵢ；lcl_res 社区聚合后表更新；2026-08-18 增补自适应裁剪 §11）

本文档解释 `fl_code/train_baseline.py` 中客户端 DP-SGD 的隐私参数
（噪声乘子 σ、裁剪范数 C、δ）的计算依据与隐私预算 ε 的完整推导过程。
所有数值均可通过 `_dp_epsilon()` / `_sigma_for_epsilon()`
（train_baseline.py，基于 Google `dp-accounting` 0.6.0 的 PLD 会计）复现。

## 0. 目标与约定

- 隐私预算控制目标（主方案文档）：**ε ≤ 8，δ = 10⁻⁵**
- 实际默认目标 **ε = 7.5**（约 94% 预算），理由见第 6 节；可用
  `--dp-epsilon` 调整（设为 8.0 即恰好花满，会计是确定性计算不会超支）
- DP 机制：**客户端本地 DP-SGD**——每个客户端在自己的本地训练中对
  **每个样本的梯度**（per-sample gradient）做固定裁剪 + 高斯加噪，
  训练结束后只上传模型更新；服务器仅做聚合（后处理），即使服务器
  不可信也无法还原任何客户端的原始数据或未加噪梯度
- **噪声乘子按客户端反解（per-client σᵢ）**：每个客户端根据自己
  的数据量 nᵢ 反解出恰好花满目标 ε 的 σᵢ；系统级 ε = max εᵢ。
  数据多（nᵢ 大）的客户端采样放大强（q = B/nᵢ 小），同一预算下
  需要的噪声少得多（第 4 节）
- **会计方法：PLD（Privacy Loss Distribution，隐私损失分布）**，
  Google dp-accounting 库，与 Schuchardt et al.（ICML 2025，
  arXiv:2502.02410）所用框架一致；比 RDP + Balle 转换更紧，
  小采样率下差距可达 2.3 倍（第 3 节）
- **隐私单位：window-level**（相邻数据集差一个 150 步训练窗口）。
  为什么不是事件级（event-level）、以及这一选择的局限，见第 7 节
- 采样放大：每个 SGD 步从本地数据集随机抽一批（B 个窗口），采样率
  **q = B/n**（n = 该客户端训练窗口数）——DP-SGD 隐私预算的主要来源
- 训练规模：每客户端每轮 `ceil(n/B) × local_epochs` 步，共 T 轮

## 1. (ε, δ)-差分隐私定义

机制 M 满足 (ε, δ)-DP，当对任意相邻数据集 D、D'（差一条记录）和
任意输出集 S：

```
Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S] + δ
```

- ε：隐私损失上界，越小越私密
- δ：违反 ε 保证的最大允许概率（本项目 δ = 10⁻⁵）

## 2. 客户端 DP-SGD 机制与灵敏度（为什么 ε 与 C 无关）

DP-FedAvg 每轮流程（隐私操作全部在客户端本地完成）：

1. 客户端 i 下载全局模型 θ_global
2. 本地 DP-SGD 训练 Sᵢ = ceil(nᵢ/B) × epochs 步，每步：
   - 随机抽 batch（大小 B，采样率 q = B/nᵢ）
   - 对 batch 内每个样本**单独**计算梯度 gⱼ（torch.func `vmap(grad)`
     实现；不用 opacus 的 GradSampleModule——它与 weight_norm 参数化卷积
     不兼容）
   - per-sample 裁剪：`clip(gⱼ, C) = gⱼ · min(1, C/‖gⱼ‖₂)`，
     强制每个样本的梯度 l2 范数 ≤ C
   - 聚合加噪：`g̃ = (Σⱼ clip(gⱼ) + N(0, (σC)²I)) / B`
   - 优化器用 g̃ 更新参数
3. 上传更新：Δ̃ᵢ = θᵢ_final − θ_global
4. 服务器仅做聚合（后处理）：θ_new = θ_global + Σ wᵢ·Δ̃ᵢ

**灵敏度推导（样本级相邻分析）**：相邻数据集差一条本地样本。
每步发布的统计量 Σⱼ clip(gⱼ) 中，单个样本的贡献最多变化 C（l2 范数）
——裁剪保证。噪声 std = σC → **noise multiplier = σ**，与 batch 大小、
聚合权重 wᵢ 均无关。

结论：**ε 只由 σ、每步采样率 q = B/n、总步数 S_total、δ 决定，
与 C 无关**（灵敏度和噪声同乘 C，相互抵消）。C 只影响裁剪偏置
（精度），是独立于隐私的精度旋钮。

注：加噪发生在梯度均值上（每步噪声 σC/B），而非最终更新上。这是
DP-SGD 与"对最终更新一次性加噪"的本质区别：前者利用 B/n 采样放大，
把每步隐私开销降到 O(q²/σ²) 量级，本项目的 ε≤8 预算因此才可行
（旧机制对 2.9 万参数模型每轮注入 ~σC·√(Σwᵢ²) ≈ 2.0 的参数噪声，
2~3 轮即淹没模型）。

## 3. PLD 会计（为什么不用 RDP + Balle 转换）

对单步机制，隐私损失是随机变量 L = ln(dM(D)/dM(D'))（输出 O 服从
M(D) 分布时取值），其分布即 **隐私损失分布（PLD）**。子采样高斯
机制（加/删相邻，灵敏度 1）的单步 PLD 由两分量混合刻画：

```
(1−q)·N(0, σ) 与 q·N(1, σ)   →   隐私损失 L 的分布
```

- q = B/n 的采样放大体现在第一分量的权重：以 1−q 的概率该样本
  根本不在 batch 里（零泄露分量），以 q 的概率贡献灵敏度 1
- 组合：T 步的 PLD = 单步 PLD 的 T 重自卷积（数值上用 FFT 实现）；
  ε 取满足 δ(ε) ≤ δ 的最小值（dp_accounting 的
  `PLDAccountant` + `get_epsilon(delta)`）

**与 RDP 的对比**：RDP 只保留各 α 阶 Rényi 散度（矩信息），再经
Balle 定理 21 转换回 (ε, δ)，两步都会引入松弛；PLD 直接刻画隐私
损失的完整分布，是当前最紧的通用会计。同机制下 RDP 报的 ε 偏大：

| 客户端规模 | RDP ε (σ=1.0, T=30) | PLD ε | 高估 |
| --- | --- | --- | --- |
| 最小客户端 n≈2305 | 6.53 | 5.94 | 10% |
| 最大客户端 n≈145 万 | 0.44 | 0.19 | 2.3× |

小采样率（大数据客户端）下差距最大。项目已从 opacus RDP 切换为
dp_accounting PLD（依赖也从 opacus 换为 dp-accounting）。

## 4. 每客户端预算反解（per-client σᵢ）

**正确性**：客户端 i 的更新 Δ̃ᵢ 是一个独立的 DP 发布，其 (εᵢ, δ)
只由 i 自己的 nᵢ、σᵢ、步数决定；其他客户端的噪声选择与 i 的保证
无关（i 的数据不出现在 Δ̃ⱼ 中）。服务器聚合是后处理。因此每个
客户端可以独立用满自己的预算：**系统级 ε = max εᵢ**。

## 5. 采样放大与组合

RDP 对组合可加；PLD 则是分布自卷积。每个客户端的总步数
S_total = ceil(n/B) × epochs × T。所有客户端取各自的最坏值——
在 per-client 模式下每个客户端恰好花满目标，不再有"最坏客户端
主导"的问题（统一 σ 模式下取 max εᵢ）。

- q 越小、放大越强：小 q 时每步开销 ≈ O(q²/σ²)，比无子采样小 q² 倍
- q 不太小时（本项目最小客户端 n≈2305、B=64 → q≈0.028），高阶项
  使放大不完全，手算近似会低估 ε，**必须以 PLD 数值为准**

## 6. 为什么默认 ε=7.5 而不是恰好 8

- 效用对 ε 是凹函数（信噪比 ∝ √ε，见第 8 节）：最后 10% 预算只值
  ~5% 的效用，边际收益很小
- 预算不可再生：ε 是这份数据一生的累计开销，重训、后续阶段加训
  都会叠加；留 ~6% 余量给未来
- 数值容差：不同版本 dp_accounting 的离散化参数略有差异
- 想榨干预算：`--dp-epsilon 8.0`（会计是确定性计算，不会超支）

## 7. 隐私单位声明：window-level 及其局限（回应 Schuchardt et al. 2025）

本项目相邻数据集的定义：**差一个 150 步训练窗口**（144 context +
6 forecast），即 window-level。这是当前实现 `q = B/n` 记账所对应
的单位。

Schuchardt et al.（ICML 2025）指出时序预测的滑动窗口高度重叠：
一个时间戳同时出现在多个窗口里。本项目 stride=6 时，**一个 30 分钟
读数出现在 25 个窗口**（24 次作为 context、1 次作为 forecast）。
若想声明事件级（event-level，保护单个时间戳）隐私，按论文框架
（Theorem 4.2 的 r = 命中窗口数/总窗口数）记账：

- 单序列客户端（steel/tetouan）：r = 25/2305 ≈ 1.1% 每窗口、
  λ=64 窗口每步 → 每步泄露概率约 50%，事件级 ε 在 σ=1.0 下约 20~60，
  **ε≤8 不可行**
- 论文的顶层采样放大（ρ = 每步序列数/总序列数）只对多序列数据集
  有效；本项目 4 个最小客户端是单序列（ρ=1），用不上
- 论文的数据增强放大（Theorem 4.5，对 context/forecast 加噪乘
  TVD 因子）需要 (w,v) 有界灵敏度，对 window-level 单位不成立

因此本项目明确声明 **window-level**：保证的是"任意一个 150 步训练
窗口的增删不可区分"。该单位弱于事件级（换算出的事件级 ε ≈ 25ε，
不提供单时间戳保护），但它是 ε≤8、δ=10⁻⁵ 约束下对单序列小客户端
唯一可行的单位。文档如实声明，不声称事件级保护。

## 8. 效用代价：DP 性能损失的固有账

DP-SGD 的效用由最终模型信噪比决定，且满足：

```
SNR ∝ n · √ε     （与 batch size、σ、轮数 T 的具体选择无关——
                  它们在同一 ε 下精确互相抵消）
```

- **小客户端（n≈2300）的退化是固有代价**：30 轮统一 σ=1.0 实测
  WAPE≈0.41 vs nodp≈0.3（+37%）。论文同量级：DeepAR 在 ε=0.5 时
  CRPS 0.157 vs 非 DP 0.124（+27%），其效果来自大数据集
  （traffic 1.5 万条序列）的放大
- 每步噪声 σC/B 构成"梯度噪声地板"：模型收敛到 |∇L| ≈ 地板处，
  表现为系统性欠拟合（大趋势学得到、细节学不精）
- **per-client σᵢ 的意义**：全局模型 = nᵢ 加权平均，3 个 eld 客户端
  权重占 ~90%（lcl_res 社区聚合 + eld_0/1 各保留最长 30 条 MT 之后）；
  eld 的 σ 从 1.0 降到 0.44~0.48（噪声地板降 2~2.3 倍）后，全局模型
  应显著接近 nodp 质量。小客户端自身指标只有 ~11% 改善（0.89 vs
  1.0；0.89 是各客户端反解值中的**最大**者，对应最小数据量客户端
  steel_ind_0/tetouan），仍是系统短板——这是 n≈2300 下差分隐私的
  诚实上限。lcl_res
  社区客户端的 σᵢ 升至 0.55~0.57（采样放大减弱），是社区聚合的 DP
  代价：曲线平滑带来的学习收益需与放大损失在实验中权衡
- 裁剪范数 C 是独立的精度旋钮（默认 1.0）：本项目 per-sample 梯度
  范数典型值 ~1-2，C 过小产生裁剪偏置，可对 {0.5, 1, 2, 4} 扫描
  校准（ε 不变）

推荐命令：

```bash

python -m fl_code.train_baseline --rounds 30 --dp-epsilon 7.5

# 恰好花满 ε=8（会计确定性，不会超支）
python -m fl_code.train_baseline --rounds 30 --dp-epsilon 8.0

# 统一 σ（打印系统级 ε 供参考；旧接口保留）
python -m fl_code.train_baseline --rounds 30 --dp-noise 1.0
```

- σ 是隐私旋钮：ε 随 σ 增大而减小（大 σ 段近似 1/σ² 比例，
  几十万步组合下曲线更陡）
- ε 随轮数近似线性增长（PLD 组合后略低于线性）
- B 增大会减少步数（训练更快），但 q = B/n 增大，ε 近似随 B 线性增大
- C 是精度旋钮（ε 不变）
- 训练启动时脚本会打印每客户端 σᵢ/εᵢ 与系统级 ε

## 10. 原理一句话总结

每个客户端在本地以 DP-SGD 训练：每步对 batch 内逐样本梯度裁剪
（灵敏度 C）并加高斯噪声（std σC，乘子 σ），B/n 子采样提供放大；
用 PLD 会计（dp_accounting）把单步子采样高斯的隐私损失分布自卷积
S_total 次，即得该客户端隐私预算 ε；每个客户端反解出恰好花满目标
ε（默认 7.5 ≤ 8）的 σᵢ，系统级 ε = max εᵢ。隐私单位明确为
window-level（150 步窗口），事件级在 ε≤8 下对单序列客户端不可行，
已如实声明。

## 11. 自适应裁剪（Adaptive Clipping）

开启 `--dp-adaptive-clip` 后，裁剪界 C 由服务端每轮按"未裁剪样本比例"
自动几何更新（Andrew et al., "Differentially Private Learning with
Adaptive Clipping", NeurIPS 2021, arXiv:2105.03820），免除 C 的人工
调参；论文证明自适应版本的隐私成本与精心调参的固定裁剪相当。隐私操作
仍全部在客户端本地完成（per-sample 裁剪 + 高斯加噪不变），服务端只
消费**加噪后**的裁剪比例标量，信任模型与固定裁剪完全一致（服务端永远
看不到未加噪梯度/更新）。

### 11.1 裁剪界几何更新

每个客户端本地统计未裁剪样本比例 f（per-sample 裁剪 scale ≥ 1 的样本
占比；本项目 scale = C/‖g‖ 并 clamp 到 ≤1，scale ≥ 1 即未裁剪），
**加噪后才上传**：

```
f̃ = f + N(0, σ_c²)     （σ_c = dp_clip_count_noise，客户端本地独立加噪）
```

服务端等权平均各客户端 f̃（独立噪声平均后 stddev 降为 σ_c/√K，与
论文/Flower 基准一致），做几何更新（Flower `DPFedAvgAdaptive` 同款
公式）：

```
C ← C · exp(−η(f̃ − τ))
```

- η = `dp_clip_lr`（默认 0.2）：更新学习率
- τ = `dp_clip_target_quantile`（默认 0.5）：目标**未裁剪**分位数；
  f̃ > τ → C 缩小（界内样本过多，说明 C 偏大），f̃ < τ → C 增大
  （界内样本过少，说明 C 偏小，多数样本被裁）
- C 每轮钳制在 [1e-4, 1e4] 防数值溢出；audit 每轮记录 C（`clip_norm`）
  供隐私预算曲线图展示

### 11.2 隐私会计：预算预支

计数机制（每轮发布加噪比例 f̃）的隐私成本**不单独入账**，而是通过调大
训练噪声乘子"预支"（Andrew et al. 2021 Thm 1 / Flower
`DPFedAvgAdaptive.__init__`）：

```
σ_train' = (σ_target⁻² − (2σ_c)⁻²)⁻¹/² ，要求 σ_c > σ_target/2
```

- σ_target 仍是 per-client 反解出的目标乘子（恰好花满目标 ε）；
- 实际训练噪声乘子取更大的 σ_train'（`adaptive_sigma_train`）；Thm 1
  保证联合机制（训练 + 计数）的真实隐私成本 ≤ 按 σ_target 记账的 ε
  ——预支在数值上是有效的上界；
- **ε 上报口径与固定裁剪完全一致**：仍按 σ_target 报 ε（冒烟实测
  σ_target=0.6028 → 上报 ε=7.4997 ≈ 目标 7.5），计数机制预算由预支
  覆盖，不新增上报项；
- **约束 `σ_c > σ_target/2`**：否则公式根号内为负（无定义），代码
  `accounting.adaptive_sigma_train` 对违例直接抛 ValueError。9 客户端
  最大 σ_target=0.89（steel_ind_0/tetouan，T=30），σ_target/2=0.445
  < 默认 σ_c=0.5 ✓；
- **独立组合会计实测不可行**（B=64, T=30, δ=1e-5, 目标 ε=7.5，计数
  机制按独立 Gaussian 事件逐轮组合）：σ_c=1.0 → ε≈39；σ_c=0.5 →
  ε≈107，均远超 ε≤8 预算（σ_c 越小计数噪声越小、泄露越大），故不
  采用；mixture 会计（`MixtureOfGaussiansDpEvent`，dp-accounting
  0.6.0 支持 PLD 组合）记为可选优化，不纳入当前实现。
